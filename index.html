ANTICIPACIÓN EL PROBLEMA DEL RUNTIME
¿POR QUÉ TYPESCRIPT EN MÓVIL?

EL COSTO DE NO TIPAR EN PRODUCCIÓN

En JavaScript vanilla, los errores tipográficos o de estructuras explotan en el teléfono del usuario.

🚨 JavaScript Vanilla (Sin Tipos)
function procesarPago(usuario, monto) { // Si usuario.perfil viene null/undefined... return usuario.perfil.descontarSaldo(monto); } // 💥 En tiempo de ejecución (App Crash en Android/iOS): // Uncaught TypeError: Cannot read properties of undefined

El error se descubre después de publicar el APK en la tienda.

🛡️ TypeScript (Seguridad Estática)
interface Usuario { perfil?: { descontarSaldo: (m: number) => boolean }; } function procesarPago(u: Usuario, m: number) { // 🛑 TypeScript bloquea la compilación antes de guardar: return u.perfil?.descontarSaldo(m) ?? false; }

0 errores en tiempo de ejecución. Autocompletado inteligente inmediato.

TRANSCOMPILACIÓN & TYPE ERASURE

¿QUÉ PASA CON LOS TIPOS AL EJECUTAR?

TypeScript es un guardián en tiempo de desarrollo. En tiempo de ejecución no existe sobrecarga de memoria.

01. ESCRIBIR
TypeScript (.ts / .tsx)

Escribes código con interfaces y tipos estrictos. VS Code analiza cada símbolo en tiempo real.

02. COMPILAR
Transpiler (tsc / Metro)

Type Erasure: El compilador elimina todos los tipos e interfaces. Genera JavaScript ultra-optimizado.

03. EJECUTAR
Hermes Engine / V8

El teléfono móvil ejecuta el bundle JS a máxima velocidad nativa sin validaciones lentas.

💡 ANALOGÍA CON JAVA: En Java compilas `.java ➔ .class (Bytecode JVM)`. En TypeScript compilas `.ts ➔ .js (JavaScript estándar)`.

SINTAXIS 1 TIPOS PRIMITIVOS
JAVA VS TYPESCRIPT

DE LOS TIPOS DE JAVA A TYPESCRIPT

En TypeScript todo número es number (64-bit). El tipo va a la derecha con dos puntos (:).

☕ JAVA (Tipado a la izquierda) Tipado Nominal
// Primitivos en Java int edad = 17; double promedio = 9.85; String nombre = "Carlos"; boolean matriculado = true; // Arrays String[] notas = {"A", "B"};
⚡ TYPESCRIPT (Tipado a la derecha :) Inferencia + Anotación
// Primitivos en TypeScript const edad: number = 17; const promedio: number = 9.85; const nombre: string = "Carlos"; const matriculado: boolean = true; // Arrays const notas: string[] = ["A", "B"];
Regla de Oro: Usa const por defecto y let solo si el valor cambiará. ¡Nunca uses var!
FUNDAMENTOS DE TIPADO SLIDE 04 / 18
SINTAXIS 2 MODELADO DE DATOS
JAVA POJO VS TYPESCRIPT INTERFACE

MODELADO DE ENTIDADES PARA APPS

En React Native no escribimos clases con 80 líneas de Getters/Setters. Usamos Interfaces limpias.

☕ JAVA: Clase DTO con Boilerplate (30+ líneas)
public class Estudiante { private String id; private String nombre; public Estudiante(String id, String n) { this.id = id; this.nombre = n; } public String getNombre() { return nombre; } }
⚡ TYPESCRIPT: Interface Concisa (6 líneas)
export interface Estudiante { readonly id: string; // Inmutable nombre: string; avatarUrl?: string; // Opcional (?) } const alumno: Estudiante = { id: "EST-01", nombre: "Mateo" };
MODELADO LIMPIO EN TYPESCRIPT SLIDE 05 / 18
CONCEPTO MAESTRO TIPADO ESTRUCTURAL
NOMINAL (JAVA) VS ESTRUCTURAL (TS)

"DUCK TYPING": LA FORMA ES LO QUE IMPORTA

En TS, dos objetos son compatibles si cumplen con los campos requeridos de la interface.

☕ Java: Tipado Nominal

Dos objetos solo son del mismo tipo si fueron declarados explícitamente con la misma clase.

class Punto2D { int x, y; } class Coordenada { int x, y; } Punto2D p = new Coordenada(); // ❌ ERROR DE COMPILACIÓN EN JAVA

⚡ TS: Tipado Estructural

"Si camina como pato y suena como pato, TypeScript lo trata como pato".

interface Punto { x: number; y: number; } const gps = { x: 10, y: 20, ciudad: "Cuenca" }; function dibujar(p: Punto) { ... } dibujar(gps); // ✅ VÁLIDO (cumple con x e y)
MODELO CONCEPTUAL DE TIPADO SLIDE 06 / 18
SUPERPODER DE TS UNION TYPES & NARROWING
MODELANDO ESTADOS DE PANTALLA

UNION TYPES & DISCRIMINATED UNIONS

En React Native modelamos los estados de las pantallas (`LOADING`, `SUCCESS`, `ERROR`) de forma exacta.

🎯 Literal Types & Union Types
export type EstadoPeticion = | "inactivo" | "cargando" | "exito" | "error"; let estado: EstadoPeticion = "cargando"; estado = "fallo"; // ❌ Error: "fallo" no existe
🔍 Discriminated Unions (Estado Completo)
type RespuestaAPI = | { status: "loading" } | { status: "success"; data: string[] } | { status: "error"; mensaje: string }; function renderUI(res: RespuestaAPI) { if (res.status === "success") { console.log(res.data.length); } }
